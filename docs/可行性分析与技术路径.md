# 玉子软件开发 · 可行性分析与技术路径

> 文档版本 v1.0 · 2026-10-20
> 目标：在 Windows 上做一个"精简、低占用、高兼容"的可视化控制台，管住 NapCat / DSH / 玉子的全部功能。

---

## 一、先给结论

**整体可行，且难度不高**——因为最难的部分（OneBot 接入、消息收发、空间点赞、共享记忆、开机自启）已经跑通了，控制台本质上是"给已有能力套一层 UI + 一个本地后端"。

预计总量：**4 个阶段、约 4 个工作日**（按一个人手写算；实际按轮次交付）。

| 你的需求 | 可行性 | 说明 |
|---|---|---|
| 1 开关 NapCat / DSH | ✅ 很容易 | 进程 + 端口 + 计划任务，已有现成脚本 |
| 2 查看聊天记录 | ✅ 容易 | 记忆库已在落盘，只需查询 + 展示 |
| 3 调试各类功能 | ✅ 可行 | 已有 11 个工具 + NapCat 全套 action 可直接调 |
| 4 功能升级入口 | ✅ 可行 | 插件目录 + 版本检查 + QQ 指令入口 |
| 5 天气 + 日程 | ✅ 可行 | 天气有免费免密 API；日程已有 `schedule.json` |
| 6 余额 + 峰谷 | ✅ 已实测 | 余额接口刚验证可用，当前 18.69 元；峰谷按官方时段 |

**真正的风险不在技术，在"状态一致性"**：控制台看到的、bot 正在跑的、NapCat 实际连的，三者必须收敛。这一点我在架构里专门处理（见第五节）。

- 一个 OneBot WS 可以**同时接多个客户端**，两个客户端并行连接都正常收到事件 → 控制台可以自己开一条 WS，不抢 bot 的连接。

- 端口占用：3001（NapCat）、3008（bot 单例锁，**别碰**）、9333（无头 Edge CDP）。控制台建议用 **3210**。

## 三、技术选型：怎么做到"精简 + 低内存 + 兼容"

四个候选，逐条比：

| 方案 | 体积 | 内存 | 兼容性 | 开发速度 | 结论 |
|---|---|---|---|---|---|
| Electron | 150–250 MB | 200 MB+ | 好 | 快 | ❌ 太重，和"精简"冲突 |
| **Node 本地服务 + Edge `--app` 窗口** | **约 1 MB** | **+50 MB** | **Win10/11 均自带 Edge** | **最快（复用现有 JS）** | ✅ **推荐 P1** |
| C# WinForms + WebView2 | 5–10 MB | 60–90 MB | 需 WebView2 运行时（Edge 已带） | 中 | ✅ 备选，做"真 exe + 托盘" |
| Tauri (Rust) | 8–12 MB | 60 MB | Win10 需装 WebView2 | 慢（要 Rust 工具链） | ⏸ 本期不做 |

**推荐路线：本地网页控制台**。

理由很实际：
- 后端必须能碰文件、碰进程、说 OneBot —— 这些 Node 已经全干过了，复制粘贴比重写快一个数量级；
- 界面用原生 HTML/CSS/JS，不引入 React/Vue，**没有构建步骤**，改一行刷新就见效；
- 窗口用 `msedge.exe --app=http://127.0.0.1:3210` 打开，无地址栏、独立任务栏图标，看起来就是个桌面软件；
- Edge 是系统自带的，不额外吃内存（本来就在跑无头 Edge 管空间）。

如果你后面一定要"双击安装、开始菜单有图标、右下角有托盘"，第三步再套一层 C# 托盘壳（约 200 行），把网页窗口装进去即可，不用改业务代码。

## 五、六项需求逐条落地

### 需求 1 · 开关 NapCat / DSH

**做法**：进程 + 端口双判定，不要只看进程名（QQ 崩溃会留僵尸进程，这个坑踩过）。

- 启动 NapCat：`NapCatWinBootMain.exe 10001`（免扫码快速登录）
- 关闭 NapCat：只杀 `D:\NapCat\` 目录下的 QQ 进程 + 后端进程，**不碰你日常用的 QQ**
- DSH：`Start-Process "D:\DeepSeek Harness\DeepSeek Harness.exe"`；关闭要先提示"这会关掉电脑端会话"
- 状态灯：3001 监听 / WS 115 心跳 / QQ 在线 / bot 进程 / Edge 9333

**风险**：连点两次"启动"会拉出两个 NapCat → 加按钮 3 秒防抖 + 后端单例检查。

### 需求 2 · 查看聊天记录

**做法**：只读 `data/brain/messages.jsonl`，按 `ch` 分频道（`qq` = 你，`qq:<uid>` = 某好友，`group:<gid>` = 群），前端做时间倒序 + 搜索 + 分页。

- 筛选：日期范围、对象、关键词、频道
- 展示：时间、说话人、内容、是否带图（`inbox/` 里能点开）
- 导出：选中范围导成 txt/markdown

**代价几乎为零**，因为记忆库从第一版就在落盘。

**要注意**：现在只存了 40 条上下文以内？不是——`messages.jsonl` 是全量追加，只是喂模型时截断。所以历史都在。

### 需求 3 · 调试各类功能

**做法**：调试台按"能力卡片"排布，每张卡一个动作按钮 + 参数框 + 返回结果框（JSON 原样显示）。

- 消息：发私聊、发群、发文件、发图片、撤回
- 回复：手动触发一次"让玉子回这句话"（验证人设/提示词）
- 空间：测试点赞、测试评论、拉起浏览器看当前说说
- 好友：模拟一条申请、通过/拒绝、查看白名单
- 群聊：给指定群发一条、开关"每条都回/仅@回"
- 系统：强制汇总日程、重启 bot、重载 .env、清理 inbox

**接口就是 NapCat 的 action**，控制台自己开 WS 调，不必经过 bot。

### 需求 4 · 后续功能升级入口

**做法**：三层入口，缺一不可。

1. **控制台内**"插件"页：扫描 `qq-bridge/plugins/*/manifest.json`，列出名称/版本/开关
2. **QQ 聊天内**：`/插件` 列清单、`/更新` 返回版本号和"打开控制台"提示
3. **升级包**：`updates/` 目录放 zip + version.json，控制台"检查更新"比对版本、一键应用并备份

**注意**：QQ 里只能"告知 + 引导"，不可能在手机 QQ 里点按钮装东西——这条边界要说清楚。

### 需求 5 · 天气提醒 + 日程

**做法**：
- 天气：Open-Meteo（**免费、不要 key**），武汉坐标 30.59/114.31，取今日最高/最低/降水概率/风力
- 推送：每天早上 `WEATHER_AT=07:30` 私聊你一句，带"要不要带伞"
- 日程：复用 `data/schedule.json` + 每日 21:30 汇总；控制台里可增删改、看今日/本周
- 开关：`WEATHER_ON`、`SUMMARY_OFF` 两个布尔写进 `.env`，控制台勾选即生效（重启 bot）

**风险**：Open-Meteo 偶尔抽风 → 失败静默跳过，别让天气挂了把日程也带崩。

### 需求 6 · 余额 + 峰谷

**做法**：
- 余额：`GET /user/balance`，每 10 分钟缓存一次，显示总额 + 今日消耗（自己记账）
- 峰谷：按官方公告，**北京时间 9:00–12:00、14:00–18:00 为高峰（原价），其余时段半价**（2026-08-17 生效）
- 展示：当前时段 + 距下次切换倒计时 + 建议（"这条不急就等到 18:00 再跑"）

**注意两件事**：
1. 峰谷规则做成可配置表（`data/pricing.json`），官方改价只改 JSON 不改代码；
2. 网上有插件说"周末全天空闲"，官方公告只写了时段没提周末 —— 我按公告实现，把"周末半价"做成开关，你确认后我再开。

## 九、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 控制台与 bot 状态不一致 | 显示在线其实掉线 | 状态一律现查（端口+WS 探活），不缓存超过 5 秒 |
| 多点一次启动出现双实例 | 双份回复 | 按钮防抖 + 单例锁检查 + 启动前探端口 |
| 关 NapCat 误杀日常 QQ | 你把主力号搞掉 | 只杀 `D:\NapCat\` 路径下的进程 |
| 聊天记录含隐私 | 泄漏 | 纯本地、不回传；默认脱敏 |
| 写 `.env` 写坏 | bot 起不来 | 备份 + 语法校验 + 一键回滚 |
| 天气/余额接口不稳 | 页面空白 | 超时 8 秒、失败显示上次缓存、不阻塞其它面板 |
| 峰谷规则变更 | 提醒错 | 规则全在 `pricing.json` |

## 十、需要你拍板的 5 件事

1. **界面形态**：先做"本地网页窗口"（轻、快），还是一步到位做"独立 exe + 托盘"（多花半天）？

3. **天气城市**：武汉？要不要同时盯你常去的第二个城市？
4. **峰谷**：按官方公告（9–12 / 14–18 高峰，其余半价），还是连周末也算全天空闲？
5. **默认开机自启**：控制台本身要不要开机自启（托盘常驻），还是需要时手动开？

## 十一、名词速查（怕你看文档时卡住）

- **NapCat**：跑在电脑上的 QQ 协议端，负责"真的登录一个 QQ"，对外提供 OneBot 接口
- **OneBot11**：一套聊天机器人协议标准，NapCat 按它说话，bot.mjs 按它听
- **DSH**：DeepSeek Harness，就是你现在开着的这个桌面程序
- **峰谷**：DeepSeek 按时段定价，忙时原价、闲时半价
- **CDP**：Chrome 调试协议，用来自动点 QQ 空间里的"赞"
